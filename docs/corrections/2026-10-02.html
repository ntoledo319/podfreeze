Publication-data correction

2 October 2026

Our previous enrichment code selected the last entry in the CocoaPods trunk API's versions array. Reversing identical records changed which release it called latest. Array position does not establish publication order.

The product now compares complete publication timestamps, including timezones. It selects the most recently published version, which can be a lower-version backport. Missing or invalid metadata, future timestamps and ambiguous latest-publication ties produce an unknown result instead of an age or priority claim. A repeated identical latest record is harmless.

We withdraw the earlier SDWebImage, Realm and Alamofire sales examples; the study's latest-version and publication-date supplement; and conclusions about which dependencies were already static. In particular, the previous SDWebImage 2020 last-release claim conflicts with the official CocoaPods catalogue, which lists 5.21.7 and February 2026 when read on 2 October. That catalogue observation is not a replacement September 15 measurement.

The corrected dataset makes the twenty affected publication records unknown. Counts based on lockfile dependency sources, the original measurement date and the non-random sampling caveat remain unchanged. The reproduction script checks an exposure summary, not publication histories. No fresh scan of the original project corpus is claimed.
